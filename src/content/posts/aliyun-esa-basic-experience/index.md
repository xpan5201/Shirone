## 一、起因：那个「打开有点慢」的小问题

之前我的博客跑在一台用 1Panel 管着的服务器上，图片放在自建图床里，用子域名单独管理。日常自己访问觉得还行，直到有朋友说「你首页的图要转两秒才出来」，我才开始认真琢磨这件事。

那阵子我做了不少功课：给图床换了更合适的存储渠道，把随机图接进了首页横幅，缓存也调了一轮。做完之后确实好了一些，但有个问题始终绕不过去——**静态资源的响应速度，还是受制于我这一台源站机器**。

后来在社区里看到大家在聊 `#阿里云ESA`，顺手了解了一下，刚好又赶上它的 `#ESA域名组合购`，算下来很贴合我这种小站的需求，于是有了这篇记录。

## 二、ESA 是什么，哪些地方比同类方案更顺手

边缘安全加速（Edge Security Acceleration）这个名字乍一看有点唬人，拆开就很朴素了：用户的请求不再直接落到我的源站，而是先到离他更近的边缘节点，能命中缓存的内容就地返回，需要动态处理的再回源；如果是静态博客或前端项目，甚至可以直接用自带的 **ESA Pages** 托管在边缘。

真正让我觉得**比同类方案更顺手**的，是下面这几处实打实的细节：

| 我关心的事 | ESA 的做法 | 为什么对我是加分项 |
| --- | --- | --- |
| 国内访问体验 | 中国内地覆盖大量边缘节点，很多落在省会等核心城市 | 我的读者大多在国内，这一项直接关系到打开速度 |
| 域名与起步成本 | **ESA 域名组合购**：购 ESA 基础版享 **1 元注册域名** | 新开个人站、折腾图床或分站域名时，起步门槛低很多 |
| HTTPS 证书 | 自带免费 SSL 证书申请与自动续期 | 忘记续签导致浏览器报红，是我踩过的坑 |
| 静态与前端部署 | 内置 **ESA Pages**，支持前端与静态博客直接边缘部署 | 加速、安全、托管收拢在一处，少折腾一层架构 |
| 配置分散 | 边缘加速、缓存与安全防护在同一套控制台完成 | 不用在几个平台之间来回切，一个人维护的站很吃这个 |
| 担心被刷 | 一键防盗刷、支持用量封顶，且**被拦截的流量不计费** | 小站怕的就是流量被恶意刷爆，这条让我踏实不少 |
| 动手成本 | 添加站点 → 改 DNS → 验证生效 | 我大概花了不到二十分钟就跑通了 |

:::tip[我个人更看重的一条]
「被拦截的流量不计费」是我觉得格外贴心的设计。做小站的人多少都有点担心流量被刷导致账单失控，有了用量封顶和拦截不计费，至少睡觉能安心不少。
:::

## 三、说说「ESA 域名组合购」：把开站前的零碎事打包理顺

一个人折腾个人博客，其实前面那几件事挺磨人的：先去比价买域名，再找地方配解析、申请免费 SSL 证书，后面为了提速还得再套一层 CDN 或边缘防护。每个环节都不算难，但散在两三个地方，真到续费或者改配置时很容易顾此失彼。

阿里云推出的 **`#ESA域名组合购`** 刚好打在这个痛点上——**购 ESA 基础版就能享 1 元注册域名**（`#1元域名`）。对我这种爱折腾小站、偶尔想单独划一个子站或测试域名的人来说，这笔账很好算：

- **花小钱把底座一次配齐**：基础版套餐本身就把边缘加速、基础安全防护、缓存控制和免费 SSL 证书包进去了，再花 1 元顺手拿下域名，省得四处凑单；
- **域名与解析天然同厂**：域名、DNS 和 ESA 都在同一个阿里云账号下，后面接入站点时解析记录点几下就能对齐，少踩很多跨域和生效延迟的坑；
- **适合静态博客和轻量前端**：如果站点本身就是 Astro 这类静态博客，配合 **ESA Pages** 做前端部署，连源站服务器的维护成本都能一并省下来。

它不是什么花哨的噱头，更像是把个人建站开头那几件零碎事打包理顺了，预算透明，心里有底。

## 四、接入过程比想象中轻

我原本以为要啃一堆术语，实际走下来就三步：

:::steps[三步完成接入]
1. **添加站点**

   在控制台输入域名，选择加速区域。
2. **配置 DNS**

   把域名解析指向 ESA 给出的地址；如果域名和 DNS 就在同一个账号下，基本是点几下的事。
3. **开启 HTTPS 并等待生效**

   申请免费 SSL 证书，解析生效后回控制台看一眼状态即可。
:::

我特意把图床那个子域名也一起接了进来，因为对我来说，**图片才是流量的主角**。缓存规则配得比较保守，先只让静态资源走缓存，动态页面保持回源，观察几天再慢慢调整——对小站来说，稳定比激进重要。

## 五、用下来的一些小感受

- **首屏体感更顺了**：以前图片是一格一格刷出来，现在基本跟着文字一起到位；
- **控制台信息够看**：缓存命中率、流量用量、请求数一眼能扫到，不用去猜；
- **源站日志安静了**：以前偶尔能在日志里看到一些莫名其妙的扫描请求，现在这类东西大多被挡在边缘，日志明显清爽；
- **配置可以慢慢来**：不必一次把规则配到完美，先跑起来，再按实际流量一点点调，这种节奏对个人站点比较友好。
